# CLAUDE.md

A first-person dinosaur stealth-horror game in Unity 6000.6.0f1 (HDRP 17.6, Input System, AI Navigation). Night with a
flashlight is the main mood. Read `docs/ESTADO-DO-PROJETO.md` first: it holds the owner's decisions, what exists, the open
decisions (including Unity versus Unreal) and the next steps.

## Working with the owner

- The owner writes in Brazilian Portuguese: reply in Portuguese. Code, identifiers and code comments stay in English.
- Design documents for the owner are in Portuguese under `docs/`. `docs/design/ilha.md` is the island design and the source
  every later build step follows.
- He works solo with AI agents and buys models and animations; everything else is built by code. Prefer code-generated,
  reproducible content over hand work in the editor.
- Do not use designs, names or inventions from Jurassic Park (the frilled, venom-spitting Dilophosaurus, Isla Nublar, InGen).
  Species names are fine.
- Commit only on request, on a branch, and open a pull request; the owner merges.

## Layout

- `Assets/Game/Scripts`: runtime code (`Gamex.Runtime`). Player, raptor AI, noise, hiding spots, flashlight, foliage
  interaction.
- `Assets/Game/Editor`: editor code (`Gamex.EditorTools`). `GreyboxSceneBuilder.cs` builds the greybox; `Forest/` is the forest
  generator (`ForestBuild.BuildAll`, menu **Gamex > Forest > Build All**).
- `Assets/Game/Shaders`: the foliage wind Shader Graphs (generated by `ForestWindShaderGraphs.cs`) and `ForestWind.hlsl`.
- `Assets/Game/Diagnostics`: the player-build frame-time harness.
- `Assets/Game/Tests`: `Gamex.Tests.PlayMode` (greybox, 7), `Gamex.Tests.Forest.EditMode` (56),
  `Gamex.Tests.Forest.PlayMode` (24, plus 11 wind tests in `ForestWindPlayTests`).
- `Tools/forest`: `fetch_assets.py` (downloads the CC0 kit by manifest, checks size and md5) and `fbx_objects.py`.
- `docs/floresta/`: how the forest was built (spec, build history, every deviation with its reason). Paths in those records
  point to the old Mac's scratch folder and are not available.

Generated and downloaded content is git-ignored and rebuilt: `Assets/ThirdParty/PolyHaven/*`, `Assets/Game/Scenes/ForestKit`,
`ForestData` and `Forest.unity`. Setup steps are in `docs/ESTADO-DO-PROJETO.md`.

## Running Unity headlessly

Windows editor path: `C:\Program Files\Unity\Hub\Editor\6000.6.0f1\Editor\Unity.exe`.

```
Unity.exe -batchmode -projectPath <repo> -executeMethod Gamex.EditorTools.ForestBuild.BuildAll -logFile <log> -quit
Unity.exe -batchmode -projectPath <repo> -runTests -testPlatform EditMode -assemblyNames Gamex.Tests.Forest.EditMode -testResults <xml> -logFile <log>
Unity.exe -batchmode -projectPath <repo> -runTests -testPlatform PlayMode -assemblyNames Gamex.Tests.Forest.PlayMode -testResults <xml> -logFile <log>
Unity.exe -batchmode -projectPath <repo> -runTests -testPlatform PlayMode -assemblyNames Gamex.Tests.PlayMode -testResults <xml> -logFile <log>
```

- Only one Unity process may open the project. If the editor is open, batch runs fail: ask the owner to close it, never kill it.
- Exit code 198 means the licence could not refresh: the owner must sign in to Unity Hub.
- Never pass `-nographics` (HDRP captures and tests need a GPU). Never combine `-quit` with `-runTests`.
- Read the test result XML, not just the exit code. Look at every image you capture.
- Select test runs by assembly, not by category: `StealthLoopTests` has no category and would be skipped.
- A player build rewrites `Assets/Game/Settings/HDRP.asset` and `Assets/HDRPDefaultResources`; restore them after building.

## Rules learned on this project

- **Performance budget:** worst standard view, median of 16-frame windows, at most 12.5 ms at 2560 x 1440 in a development
  player build with vsync off and the flashlight on. Measure only on an idle machine: background apps made the same build read
  17 ms instead of 10.5 ms. Per-frame medians are unreliable with vsync off. Re-measure on the Windows machine before trusting any
  number.
- **Checks:** never make a check pass by weakening it. A test that pins a tunable may change with that tunable, with the reason
  recorded; correctness checks (grounding, clearances, corridors, missing materials, determinism) stay as they are.
- **Greybox:** treat the greybox scene and its tests as protected. Forest work must not change them.
- **Subagents:** keep their shell commands short and plain, with absolute paths. Several agents hung forever on compound
  commands that began with `cd` and on long `bash -c` one-liners.
- **Records:** keep them in the repository or another persistent folder. A temporary folder lost files after a few days.
